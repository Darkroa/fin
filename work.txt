FINAI MT5 BROKER CONNECTION + AI TRADING WORK PLAN
==================================================

Scope
-----
Add MT5 broker accounts to the FinAPI area of the web profile. Initial broker choices:
FBS, Octa, Exness, IC Markets, XM, Pepperstone, HFM, Deriv, RoboForex, and "Other MT5 Broker".
The connection is a broker account connection, not a crypto exchange connection.

MetaApi Cloud architecture
--------------------------
MT4 and MT5 brokers use different server names and terminal gateways, so FinAi
must not connect directly from the browser or pretend that all brokers share one
login API. The authenticated backend provisions each account through the official
MetaApi Cloud SDK.

The production flow is:

1. The user opens Profile > FinAPI > MetaTrader Accounts.
2. The user chooses a broker and platform, then enters the account number, exact
   broker server, and trading password.
3. The browser sends the form to FinAi only. It never talks directly to MetaTrader
   or stores the password in browser state/local storage.
4. The backend calls MetaApi with the server-side `METAAPI_KEY`, deploys a cloud
   terminal, waits for broker verification, and receives a unique account ID.
5. FinAi stores only the MetaApi account ID and masked metadata. MetaApi retains
   the broker credentials inside its managed terminal service.
6. Later account, market, quote, and order requests use the account ID plus the
   server-side token through the MetaApi Python SDK.
7. If MetaApi is unavailable, the UI shows the provider error and never invents
   balances, quotes, positions, or fills.

MetaApi dashboard behavior
--------------------------
For each saved MT5 account, show:
- broker, platform, account mask, server, demo/live status, MetaApi status;
- Sync button;
- balance, equity, free margin, margin level, currency, open positions;
- positions and orders returned by MetaApi;
- last successful sync time and a clear provider error when unavailable.

The FinAPI page supports multiple MT4/MT5 accounts. A label such as "Exness main"
identifies the account for AI analysis and order routing. Disconnecting one label
also removes only that account's MetaApi cloud terminal.

Market search and analysis
-------------------------
1. Search calls MetaApi so the results use the user's actual broker symbols
   (for example, XAUUSD, XAUUSDm, EURUSD, or a broker-specific suffix).
2. Selecting a symbol stores the selected broker symbol and its latest bid/ask context.
3. Fin AI receives the symbol and available live market context through the existing
   /api/ai/chat route.
4. AI analysis must return trend, momentum, key levels, entry zone, invalidation,
   stop-loss, take-profit, risk/reward, confidence, and a statement when conditions
   are not tradeable.
5. Analysis is advisory only. Asking for analysis never places an order.
6. The AI must not guess a price when MetaApi has no live quote. It should say
   that live quote data is unavailable and ask the user to retry.

AI-assisted trade flow
----------------------
1. User selects the real broker symbol.
2. User asks Fin AI for analysis.
3. User reviews the analysis and chooses buy or sell, lot size, stop-loss, and
   take-profit in the explicit trade panel.
4. The API checks the selected account, demo/live state, live-trading permission,
   symbol, volume, margin, and risk controls.
5. The UI shows a final confirmation that includes broker, account mask, symbol,
   side, lot size, stop-loss, take-profit, and demo/live mode.
6. Only after confirmation does the API call MetaApi's market-order SDK method.
7. The result is shown with the MetaApi order ID, fill status, and any rejection reason.
8. Every action is audit logged without credentials: analysis request, confirmation,
   rejected order, submitted order, fill, and disconnect.

Safety and security requirements
--------------------------------
- Demo mode is the default.
- Live trading is off by default and cannot be enabled for a demo account.
- Never place an order from an AI response automatically.
- Require explicit final confirmation for every order.
- Require stop-loss and enforce maximum risk/drawdown settings before enabling
  unattended bot execution.
- Keep the MetaApi token server-side and never persist broker passwords in FinAi.
- Do not expose MT5 passwords in _user_dict, browser state, logs, error messages,
  AI context, or analytics.
- Mask account numbers and server-side identifiers in the UI.
- Add rate limits and idempotency keys to order requests so browser retries cannot
  duplicate a trade.
- Treat broker/provider connectivity as untrusted: validate every MetaApi response.

Decision — MetaApi Cloud SDK provider
-------------------------------------
The old mtapi.io integration has been removed. FinAi now uses the official
`metaapi-cloud-sdk` Python package and the MetaApi Cloud service at
`https://metaapi.cloud`.

Implementation update — 18 August 2026 (MetaApi + standalone dashboard)
-----------------------------------------------------------------------
- FinAPI provisions an MT4 or MT5 cloud terminal from the selected broker,
  account login, trading password, exact server name, and platform.
- MetaApi verifies and deploys the terminal, then returns a permanent MetaApi
  account ID. Only that account ID is stored in the user's connection record;
  the broker password is never persisted or returned to the browser.
- The backend uses `METAAPI_KEY` and the stored MetaApi account ID for account
  information, open positions/orders, broker symbol search, live quotes, and
  explicit market orders.
- FinAPI remains the connection and verification screen. MT Dashboard remains
  the account sync, market search, Fin AI analysis, and explicit order screen.
- Multiple broker accounts are supported independently, and disconnecting one
  removes its corresponding MetaApi cloud account.
- `requirements.txt` now includes `metaapi-cloud-sdk`. Configure `METAAPI_KEY`
  through the Replit secret store before connecting real broker accounts.
